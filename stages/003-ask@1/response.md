First-round questions — no plan has been proposed or rejected yet, so these are the pre-build decisions where the goal genuinely underdetermines the build. Things I'm deciding myself (say so now if you disagree): keep the `web_search` tool schema and output format identical (Venice precedent); keep the no-fallback-between-backends policy; no auth support initially (URL only — matches the trusted local deployment model); httpmock unit tests like Venice's, no live e2e requirement; configuration follows the `DAYTONA_API_URL` precedent (env/settings lookup, not a vault secret, since a URL isn't a credential); doctor gets a reachability probe with "start SearXNG and set the URL" remediation.

1. **What does "runs locally" mean here?** (a) Fabro just *integrates*: operator runs SearXNG themselves, Fabro points at its URL — smallest change; (b) Fabro *ships and manages* a bundled SearXNG container alongside the server — bigger, touches install/compose/lifecycle; (c) no local service at all: in-process scraping of public engines (DDG etc.) from Rust — no Docker needed, but fragile and ToS-questionable. I'm assuming SearXNG is the intended engine; correct me if you had something else in mind.

2. **When both a local URL and Brave/Venice keys are configured, which wins?** (a) Local first — cheapest wins, matches the cost motivation; (b) keys keep priority — local is used only when no key exists, so current users see no change; (c) an explicit `web_search backend = ...` setting decides, presence-based inference goes away.

3. **Do we ship SearXNG in the compose files?** (a) Add a `searxng` service to `docker-compose.yaml` (and which of the other variants — prod/local/split-web); (b) an opt-in compose profile (`--profile search`) so it's off by default; (c) docs only — compose stays untouched, operators wire it themselves.

4. **Default URL or require explicit configuration?** (a) Default to `http://localhost:8888` (SearXNG's default port) so a stock local install works with zero config; (b) no default — the backend is inert until a URL is explicitly set, avoiding accidental behavior when something happens to listen on that port.
